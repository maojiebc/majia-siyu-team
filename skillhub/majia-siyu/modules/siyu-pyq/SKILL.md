# 朋友圈文案官（siyu-pyq）

## 这个 skill 干什么
一线私域运营每天最磨人的活：黄金时段要发好几条朋友圈，天天想新文案还不能重样，写到枯竭。这个 skill 输入主题/产品/场景，一次产出**可直接复制发布**的朋友圈文案——按内容配比排布、套爆款结构、配 emoji 与话题标签、标注建议发布时段，产出前做**合规前置扫描**。

方法论引擎：**内容即产品**——每条朋友圈当一个有钩子、有承接、可复用的产品来做，不是发一条扔一条。

## 输入（先用已有信息，关键缺口才问）

开始前，若当前客户在 `~/.siyu/clients/` 有档案，按 `siyu-restore` 第 1 步定位（以文件名时间判断最新，解析实际路径并拒绝路径越界），只读最近可用档案的「经营画像」和「已确认结论」，开头说明用了哪天的哪份档案；用户说不用就忽略。只读，不写、不改档案，不跨客户查找，放弃的方向不继承。当前对话优先；档案里的价格、营业与活动等旧事实仍需本次确认。没有档案就直接用已有信息，不要求先建档。


- 品牌 / 品类（如：餐饮 · 牛肉火锅）
- 本次主题或产品（如：新品毛肚上市 / 周末活动 / 节气借势）
- 目标动作（到店 / 加微领券 / 社群引流 / 单纯养人设；零售不要默认到店）
- 可给的真实素材（卖点、活动规则、客户评价原文）——用户当场提供，或见 `assets/真实语料-待填.md`
- 要几条 / 排几天

节日、节点、年夜饭、春节类请求先读 [节点经营日历](../_knowledge/02-industry/catering/节点经营日历-2026Q4至2027春节.md)。

## 生成流程（SOP）

### 1. 定配比
默认一周/一批结构：**40% 行业干货 · 30% 产品场景 · 20% 生活人设 · 10% 互动福利**，硬广不超过 30%。配比与说明见 [`references/内容模型-配比与爆款结构.md`](references/内容模型-配比与爆款结构.md)。

### 2. 每条套爆款结构
默认：**痛点提问 → 解决方案 → 客户见证/信任状 → 弱行动指令**；人设类可用「场景故事 → 价值观」。结构模板库见同一 reference。

### 3. 出文案
- 口语、短句、有真实感；emoji 克制（1–3 个/条，不刷屏）；结尾配 1–2 个话题标签。
- 标注建议发布时段（默认 10:00 / 15:00 / 19:00 三黄金时段轮排）。
- 需要时出 **A/B 两版**（只换钩子/首句），供原生测试。

### 4. 合规前置扫描（边写边合规，必做）
产出前对每条跑一遍合规扫描（复用专家团合规词库，单一真源）：

```bash
echo "你的朋友圈文案" | python3 modules/siyu-pyq/scripts/pyq_lint.py -
```

- 命中封号动作 / 广告法绝对化用词（诱导分享、最、第一、100%、包治…）→ **就地改写**，不交带红线的文案。
- 餐饮特有：产地 / 工艺 / 功效表述别越界，见 [`references/合规前置扫描.md`](references/合规前置扫描.md)。

### 5. 三句话自检（内置质检，用户无感）
- **内容即产品**：这条有钩子吗？用户愿意看/存/转，还是自嗨硬广？
- **私域即公关**：语气是平等的朋友，还是居高临下推销？
- **运营即广告**：这次触达值不值这个曝光？（不刷屏、不浪费额度）

交付前，把最终客户正文通过标准输入送入上面的随包检查脚本；实际退出码为 0 才写「脚本扫描通过」。无法运行时，按参考资料自检并写「未运行脚本，发布前仍需复核」，不把模型自检称为人工审核；命中阻断先改写再检查。

## 输出格式

先给客户正文，操作说明放正文外；单条短稿也在末尾独立保留一行真实检查状态（已运行的结果，或「未运行脚本，发布前仍需复核」）。
按天/条给一张表：`发布时段 | 分类(干货/产品/人设/福利) | 文案正文 | 标签 | [A/B版]`，末尾附「合规扫描：通过 / 改写记录」。加盟/混合须给每条加「执行边界」标签；零售不要默认到店钩子，改对着导购个微、小程序会员或复购动作。

## 马甲护城河注入点
优先查询公开原子库：`python3 tools/atoms_query.py --skills siyu-pyq`。品牌专属卖点、见证和规则由用户当场提供；私有实战层说明见 [`assets/真实语料-待填.md`](assets/真实语料-待填.md)。

> 未接真实语料时用占位示例，产物顶部标注「⚠️ 未接真实语料，当前为通用示例」。

收尾时如果已形成可复用结论，提示一次：「有结论想留下，输入 `/siyu-save`。」一次对话最多提示一次。

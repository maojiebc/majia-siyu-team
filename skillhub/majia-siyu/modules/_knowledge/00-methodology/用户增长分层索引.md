# 用户增长知识分层索引

## 为什么分两层

从原始语料重拆时遵守：

- **L0**：只放跨行业仍成立的结构（主要来自大宁用增方法骨架）  
- **L1**：只放餐饮零售/私域/加盟的壳与牙（大大张、私域笔记、餐饮册、Nowledge 约束）  
- **L2**：客户真实 SOP（私有，不进公开库）

合并成一层会：要么空，要么不可迁移。

## 后台路由约定（已实现）

代码：`src/siyu_team/knowledge/growth_layers.py` + `routing.route_task`

| 条件 | 加载 |
|---|---|
| 未声明 `industry` | 只 L0 文档 |
| `industry=catering` 或 `retail` | L0 + L1 餐饮零售文档 |
| `industry=edu` 等其它 | 只 L0（尚无专属 L1） |
| 任务=市场调研 | **不**加载增长层（防内部方法冒充外部事实） |

`RouteDecision.focus` 会附带一句人话说明当前加载了哪一层。

## 原子 ID 规则（已实现）

- 文档锚点逻辑 id：`L0-01` … `L0-16`，`L1-C01`…，`L1-01`…  
- `source_id = src_` + sha256(文档稳定路径)[:12]  
- `atom_id = ka_` + sha256(source_id + locator + 0)[:16]  
- 正式集：`modules/_knowledge/04-atoms/growth-layers.approved.jsonl`（`review_status=approved`，进 Pilot 正式集与诊断上下文）  
- 主题标签：`growth_l0` / `growth_l1_catering`  
- 重建：`PYTHONPATH=src python3 tools/build_growth_atoms.py`  
- 按业态读原子：`load_growth_atoms(industry)`

## 1. 业态约束（不写进 L0 的硬壳）

### L1-C01 加盟默认：别假设门店会照做

- **判断**：总部策略的真实产量 = 设计 × 门店执行率；执行率由「好不好做 + 店里有没有好处」决定。  
- **来源**：Nowledge 加盟规则；餐饮私域「前期团队理解与到店转化」。  
- **怎么干**：每个动作写清店员最小步骤、耗时、归到店的好处；抽检执行，不只看结果数。  
- **失效**：方案只在总部飞书好看。

### L1-C02 企业微信是可复制的底子，个微有活人味但难复制

- **判断**：连锁要规模，优先企业微信地基；个微人情要靠内容和活动补。  
- **来源**：餐饮册企微 vs 个微；大大张「三家店以上建议换企微」。  
- **怎么干**：冷启动先齐四件套（好友码→资料页→好友欢迎语→群活码）；**先加好友再进群**（朋友圈+私聊+群，三路都戳得到）。  
- **失效**：只有个人微信群，人走客走。

### L1-C03 关键行为是「到店/核销/下单」，不是「已读」

- **判断**：餐饮增长的胜利条件默认是到店或成单；私域触达若接不到店，只是噪音。  
- **来源**：大大张反复强调到店转化累积；偷着打折闭环到平台交易。  
- **怎么干**：每条群发/朋友圈写「希望他几天内做什么」；能核销的钩子优先于纯互动。  
- **失效**：群很热闹，店里没多一个人。

### L1-C04 复购周期由品类决定，沉默阈值不能抄互联网 7 日

- **判断**：快餐/饮品与正餐/火锅的「该回来的天数」差很多；沉默与召回阈值必须按品类定。  
- **来源**：餐饮册 stages「复购周期差异大」；L0-06 的业态化。  
- **怎么干**：冷启动先问品类与堂食外卖占比，再定 N 天沉默。  
- **失效**：全国一刀切 30 天召回。

### L1-C05 合规是前置：私域不是法外之地

- **判断**：诱导分享、绝对化承诺、乱收集信息，会直接炸掉账号与信任。  
- **来源**：私域公理「合规前置」；清朗后「从流量思维到用户价值」。  
- **怎么干**：生成动作时就拦；裂变走官方允许路径。  
- **失效**：先追「一个老客带几个新客」，再补合规。

## 3. L1 专有 Know-how 原子（原始语料直接下沉）

### L1-01 私域五步是增长的骨架，不是群发日历

- **判断**：造 IP → 做链接（把人加上来）→ 促活 → 分层 → 复购；人没加上来，后面全是空转。  
- **来源**：大大张「私域拉业绩」系列结构（造 IP/做链接/促活/做分层）；仓库餐饮五步。  
- **怎么干**：冷启动只打「加得上、留得住」；扩张才加码分层与召回。  
- **阶段**：cold → growth → mature（见 stages.md）。

### L1-02 加微路径要拆「看到 / 扫了 / 加上了」

- **判断**：加人不动时，先分清是码没人看见、扫了没过、还是过了又删，再改。  
- **来源**：L0-08 的业态化；门店现实与 Golden 加微题同构。  
- **怎么干**：门店×时段记三步；一次只改位置/话术/钩子之一。  
- **失效**：只盯后台「今日新增」。

### L1-03 收银按新老客分别引导

- **判断**：收银引导先识别顾客状态，只承诺当下能兑现的权益。
- **来源**：门店运营资料脱敏整理，见 [门店会员执行参考](门店会员执行参考.md)；为编辑判断，未验证普遍经营效果。
- **复核日期**：2026-09-14
- **审阅者**：Codex editorial review under maintainer authorization
- **条件**：有可核实的活动规则；能区分会员身份；门店可正常结账。
- **怎么干**：新客给一个领礼动作，确认当单适用后再说明省多少钱；老客提醒出示身份或用已有券。高峰减少非必要步骤，顾客拒绝就正常结账。物料放在指得到的位置。
- **指标**：有效注册转化率|同一批被引导顾客中首次有效注册人数除以可观测被引导人数，无法关联时不计算|同一门店同一观察期
- **失效**：新老客都重复注册；权益尚未确认就承诺当单减钱。
- **边界**：系统已自动识别会员时不要重复登录；活动不适用当单时改说真实领取规则。
- **绑定**：siyu-huashu|siyu-wenzhen|ops-as-ad-funnel
- **场景**：收银话术|收银引导|新客老客

### L1-04 先兑现领礼承诺，再承接进群

- **判断**：好友入口承诺了权益，就先兑现权益，再说明进群用途。
- **来源**：门店运营资料脱敏整理，见 [门店会员执行参考](门店会员执行参考.md)；为编辑判断，未验证普遍经营效果。
- **复核日期**：2026-09-14
- **审阅者**：Codex editorial review under maintainer authorization
- **条件**：顾客已添加服务账号；群承接是可选动作；原入口有明确权益。
- **怎么干**：先帮助领礼，再给可选入群入口。新客主物料引导加好友；已注册且领礼的顾客可用独立进群入口，两种物料标清对象。
- **指标**：领礼后入群率|同一批已成功领礼、领礼时尚未入群且适合邀请并可关联身份的顾客中，新增入群人数除以该批符合条件人数|事先约定的承接观察窗
- **失效**：礼没领到就不断加步骤；用群人数代替新增会员。
- **边界**：已自动入群或明确拒绝就不再邀请；各阶段身份不能关联时不得拼接转化率。
- **绑定**：siyu-huashu|siyu-qunfa|siyu-wenzhen
- **场景**：领礼|进群承接|领完礼

### L1-05 分层就是把「财神爷」标出来，标签必须能对应行为

- **判断**：分层=标签分类；没有点击/消费行为垫底，工具和 AI 都没用。  
- **来源**：大大张《做分层》：福利/单次/金额/对人好等标签；连锁用企微；单店可用微信标签低成本起步。  
- **怎么干**：  
  - 最低配：微信标签 + 群发助手，按是否领福利、是否消费、客单、是否好说话标记；  
  - 标准配：消费数据打标，社群系统只读标签。  
- **失效**：标签很多，但和有没有来吃饭对不上。

### L1-06 活动私域首发、平台联动——「偷着打折」

- **判断**：更大折扣的套餐在平台建完先隐藏，只把码/链发到私域；成交仍记平台热度，又不打乱前台公开价。  
- **来源**：大大张「偷着打折」原文结构。  
- **怎么干**：平台建隐藏套餐→审核隐藏→私域发码（朋友圈/群/一对一）→到店/平台核销。  
- **边界**：折扣要有意义；表述真实；不要靠假稀缺违法。  
- **阶段**：growth / mature。

### L1-07 公私域要闭环到同一笔交易

- **判断**：私域爽、平台也要有热度/订单记账，两头都落到交易，才算增长而不是自嗨。  
- **来源**：偷着打折「公益和私域形成交易计划」。  
- **怎么干**：私域钩子尽量落到可统计的核销/订单；能对账。  
- **失效**：私域只抽奖不闭环。

### L1-08 召回要有停止和转人工条件

- **判断**：召回先核对可联系对象和服务问题，再给到店理由与停止条件。
- **来源**：门店运营资料脱敏整理，见 [门店会员执行参考](门店会员执行参考.md)；为编辑判断，未验证普遍经营效果。
- **复核日期**：2026-09-14
- **审阅者**：Codex editorial review under maintainer authorization
- **条件**：已知最后有效消费、近期联系、许可和服务处理状态；周期与权益由业务确认。
- **怎么干**：按新品、真实权益等给出理由；每次设观察截止与联系上限。已拒收、已回流、重复命中或服务问题未处理的，排除或转人工。无响应先查送达、权益与门店服务。
- **指标**：观察窗回流率|符合圈选条件的被联系会员中窗口内有效回流人数除以该批被联系会员人数；不是增量|联系后约定的完整观察期
- **失效**：把群内不说话当流失；没有回流就无限加大发券。
- **边界**：没有消费或联系数据只能提待核假设；心理原因不能由未到店天数推断。
- **绑定**：siyu-wenzhen|reactivation-playbook|siyu-qunfa
- **场景**：召回|停止触达|服务问题

### L1-09 内容要有用，才能当产品卖信任

- **判断**：私域内容若没有使用价值（吃法、搭配、避坑、到店指引），就只是广告垃圾站。  
- **来源**：私域公理「内容即产品」；3322 配比在餐饮册（美食/吃法/日常/福利）。  
- **怎么干**：福利占比受控；先给用得上的，再给优惠。  
- **失效**：一发就打折。

### L1-10 老客从个微迁企微：先引后弃

- **判断**：不要一上来宣布解散老群；先用新群专属钩子引一波，再谈迁移。  
- **来源**：仓库老客迁移 SOP。  
- **怎么干**：老群发带钩子物料→加企微→欢迎语推群→观察进入率→再处理老群。  
- **失效**：一刀切伤感情，人走光。

### L1-11 冷启动只打地基指标

- **判断**：0→1 阶段主指标是加得上、接得住，不是裂变和会员等级炫技。  
- **来源**：stages cold；大大张系列前置「造 IP/做链接」。  
- **怎么干**：第一周四件套 + 钩子库（进群福利/到店礼/收银口播/物料位）。  
- **失效**：冷启动就上复杂会员+裂变。

### L1-12 扩张阶段主打分层与再来；成熟才规模化带人

- **判断**：growth=分层+再来效率；mature=合规带人+会员体系复制。  
- **来源**：stages.md。  
- **怎么干**：阶段没到不要跳步；用 L0-11 看活动是否在乱放量。  

### L1-13 诊断必问业态变量

- **判断**：不问门店数、客流、客单、堂食外卖、复购周期、现有钩子，就给增长方案 = 算命。  
- **来源**：stages 餐饮特有变量。  
- **怎么干**：问诊开场先要这六项（与开场摸盘一致）。  

### L1-14 从流量思维转到用户价值

- **判断**：清朗与平台规则变化后，靠刺激性玩法硬收割的空间变小；要转到可重复的用户价值与关系。  
- **来源**：清朗行动后私域转型笔记取向。  
- **怎么干**：策略评审先问「这是存信任还是花信任」。  
- **失效**：只追短期核销不顾退群。

### L1-15 新店开业前先走通一次

- **判断**：开业宣传前，要让顾客从入口到付款及报表回收走通一次。
- **来源**：门店运营资料脱敏整理，见 [门店会员执行参考](门店会员执行参考.md)；为编辑判断，未验证普遍经营效果。
- **复核日期**：2026-09-14
- **审阅者**：Codex editorial review under maintainer authorization
- **条件**：已确定活动目标、库存、毛利承受范围及执行人员。
- **怎么干**：店长演练门店入口、会员识别、领券、商品适用、付款和门店归属。总部给规则，区域核配置，店主定预算。测试记录要标记并排除经营统计，失败先修再宣传。
- **指标**：活动路径完成率|同一批可观测活动参与顾客中完成目标行为人数除以该批参与人数，注册与首购分别报告|同一活动周期，首购后复购另设完整窗口
- **失效**：后台配置完就称门店已执行；同时堆叠无法解释或兑现的活动。
- **边界**：具体菜单和系统能力需当次核验；无库存或核销能力就缩减活动。
- **绑定**：siyu-wenzhen|ops-as-ad-funnel
- **场景**：新店开业|开业活动|活动选型

### L1-16 有券用不了先拆操作与配置原因

- **判断**：核销失败先定位身份码、券码、操作顺序和授权配置，不直接归因为顾客没兴趣。
- **来源**：门店运营资料脱敏整理，见 [门店会员执行参考](门店会员执行参考.md)；为编辑判断，未验证普遍经营效果。
- **复核日期**：2026-09-14
- **审阅者**：Codex editorial review under maintainer authorization
- **条件**：知道失败步骤、错误提示和影响范围；管理员权限边界明确。
- **怎么干**：收银员核对码与入口；区域或管理员核对按钮授权、商品映射和配置下发；技术支持查终端网络及版本。只在必要内部渠道提供去敏报障材料，修复后重走失败路径。
- **指标**：核销异常解决率|同一观察期已复测通过的异常数除以受理异常数；另报未解决及待观察项|受理至约定复查日
- **失效**：反复让顾客换码或重付；后台下发成功但未确认门店恢复。
- **边界**：公开方法不指定厂商当前菜单；退款和现场补偿须由有权限的人按实际规则处理。

## 4. 餐饮默认漏斗与指标壳（L0-04/08 的填空）

```text
进店或看到物料
  → 扫码
  → 加上企业微信（有效加微）
  → 进群（可选但推荐）
  → T 天内首单到店/核销
  → 观察窗内再来
  → 沉默预警 → 召回
```

| 指标（人话） | 建议定义 |
|---|---|
| 有效加微 | 加上且短时未删 |
| 加微率 | 有效加微 ÷ 曝光或进店人次 ÷ 同周期 |
| 首单 | 加微后 T 天内到店或核销 |
| 再来 | 观察窗内 ≥2 次消费 |
| 拉客成本 | 礼+券+可归属人力+物料 ÷ 有效加微或有效首单 |
| 戳人成本 | 退群/屏蔽 + 人力 |

具体 T、N、阈值 → 业务共创或 L2，不写死在公开 L1。

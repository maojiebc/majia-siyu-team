# 把内容当产品做（选题/钩子/承接）

## Overview
对齐方法论引擎「内容即产品」。本 skill 给方法论框架与通用模板。

## 方法框架（行业通行版，真实配比/话术见护城河注入点）

内容当产品做，盯三件事——有人看、有人存、有人动。

1. **选题从处境反推，不从灵感出发**：先问这条内容替用户解决当下哪个具体处境（今天吃什么 / 怎么点不踩雷 / 家里来客怎么办），再定题。用户的真实提问、评论、客服高频问题是选题富矿。
2. **钩子放前三秒 / 首图首句**：图文看首图能不能让人停，视频看前 2 秒有没有由头。钩子不是标题党，是把「跟你有关」在第一眼说清。
3. **承接服从内容任务**：行动型内容说明点哪里、说什么及必要条件；服务先解决问题，品牌或审美内容可以不带购买动作。
4. **跑通就沉成模板**：一条内容跑通后沉成结构（选题角度 + 钩子形态 + 承接方式），下次填变量即可，不每次从零想。

> 马甲实战层（真实 SOP 与语料）属于私有咨询增值层，不随公开包分发；公开层提供通用模板与方法。

## 文案与配图

先读 [分渠道文案与触达节奏](../_knowledge/00-methodology/分渠道文案与触达节奏.md)，按读者任务、渠道和真实事实组织内容；需要图片时再读 [文图协作与生图简报](../_knowledge/00-methodology/文图协作与生图简报.md)，选择场景、比较、搭配、步骤或价签结构，交可执行简报。用户要图且有工具时生成并检查，否则说明未出图，不把提示词当成成图。

首句与首图合看，避免各说各的；图片简报用一行线框确定阅读顺序，另列准确文字，并说明文字区与入口区如何留空。只完成用户所需的一条稿或一张图，不自动扩成案例库、行业模板全集或整套内容系统。

## 按请求交付
写作任务先给成品，按需读 [社群表达与成品示范](../_knowledge/00-methodology/社群表达与成品示范.md)。朋友圈、群消息、私聊分别按阅读与回应方式表达，emoji、框线、情绪和口语属于创作工具，不套咨询报告的克制口吻。

配图任务交明确的构图选择与准确文字，需出图时完成生成和检查。整盘内容规划才列动作、人群、时间、责任人与指标；一条文案或一张图不强制附行动表、ROI或风险清单。事实检查与风险修正在后台完成，未解决且影响使用的事项集中说明。

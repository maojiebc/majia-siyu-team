# siyu-market-research：私域市场调研

由入口接力时，沿用原始条件和已核验事实，只完成本步交付；待核假设不得升级为事实。

先判断需要解决什么，再查候选。来源齐全不等于适合采购，平台背景不等于接口打通。

## 一、先确定回答到哪一步

- 只问“需要什么系统”，先识别现有系统、主要问题和经营模式。已有条件直接用；最多补问一个最影响判断的问题。可先给条件性判断，不凭店数断言必须买四层系统、上储值或替换收银。
- 只问调研范围或比选方法，直接给方法；可讨论用户提及的平台及待调查方向，不需先证明所有产品在售。
- 用户提供名单或资料，可逐项分析并引用，明确“基于所给材料的初筛，未独立实时核验”。不能把用户说“倒闭了”升为已证实破产，也不能因不能联网而拒绝分析现有资料。
- 需要新增具体候选或确认当前状态，必须公开联网检索。新候选来自本次检索，不能凭模型记忆列名单再补链接。不能联网就说明限制，不新增名单、不宣称已核验或给正式采购推荐。
- 需求初判不等于采购建议；证据不全仍可说明已知问题和下一项验证，不用空表格充数。

## 二、候选覆盖与平台资源

按用户主要获客渠道、现有工具和需贯通的交易路径，覆盖相关的平台自营方案、平台生态服务商、独立餐饮系统；沿用现有系统加接口也是选项。

餐饮涉及团购/到店/外卖时，默认把美团生态纳入公开检索范围；涉及微信会员/企微、支付、小程序、内容获客时，相应查看腾讯/微信、阿里/支付宝、抖音等生态；百度等方向按实际获客路径决定。这些只是检索方向，不预设平台存在合适产品，不要求四家凑齐。最终报告交代相关方向为何纳入、排除或待核，不能漏掉主要渠道却声称全面。

用户偏好平台资源时优先考察，但区分平台自营、控股、参股、认证服务商、普通接口合作。投资/认证/Logo 不证明持续资源支持，不证明获得流量；合作意向不作为推荐加分。

用同一场景核对：公域订单/团购券 → 到店核销 → 自愿入会或加企微 → 再次消费记录。每段注明自动、人工或不支持，查主体、账号/门店权限、顾客授权、接口开放范围、数据导出、费用及退出成本。能核券不等于订单、会员身份和企微客户互通，不要求平台未授权的数据。

只按已核验且符合用户条件的能力比较，不把平台厂商一律排在独立厂商前面。

## 三、正向与反向核验

每个拟推荐对象分别记录以下事实，不能用首页替代：

| 事实 | 证据与边界 |
|---|---|
| 主体状态 | 可核验登记或对应主体资料；品牌、签约、收款主体分清 |
| 产品仍售 | 近期版本/帮助文档、官方产品和销售信息交叉核对；网页能打开不等于正在交付 |
| 功能与接口 | 当前官方文档的范围、版本、权限与限制；营销页只算厂商自述 |
| 价格 | 官方价格页或有日期的有效报价；无证据不估价，费用范围未知就写未知 |
| 案例 | 标注厂商自述、客户确认或独立报道；大客户案例不自动适用小连锁 |
| 履约风险 | 检索拖欠结算、提现异常、停服、重大纠纷、欠薪/收缩及后续；优先官方记录、可信原始报道 |

反向检索同时用品牌名与已确认主体。区分检索日期、事件日期、来源页面日期和解决证据；抓取日期不是事件时间。未搜到风险不等于安全；旧风险不能假装今天发生，也不能因年代旧自动清除。

重大资金/停服风险未查清，或只有销售口头解释，暂停推荐，说明缺什么解决证据。传闻写待核，不自行宣布破产。无可靠在售证据的对象不进入推荐，必要时仅作为排除理由，不再加“产品线最全”等背书。

## 四、证据支持到哪，就说到哪

每条影响推荐的关键结论附具体来源页链接、页面日期（不可得写未知）、本次查阅日期及支持的事实。域名、统一核验日期、搜索摘要都不足以证明整行功能和优劣；重要来源打开原文。矛盾来源并列保留，未解决前缩小结论。

分别标注主体/在售/风险/适配状态，不能用“已核验在营”概括四项。阶段用“材料初筛 / 可进入演示试用 / 暂停推荐”；关键条件、证据、风险及实际验收相符后才给采购判断。禁止无对比证据的“最全、最强、优于某家”。

先给当前能成立的判断和理由，必要时用短表，详细证据放后面。实时检索可用“市场调研快照｜核验日期：YYYY-MM-DD”；离线分析必须标明性质，不能挂当天日期冒充实时调研。只保留会改变选择的待核事项，不固定推销下一项服务。

## 五、交付前复核

对照原要求与证据检查事实、适配、风险、覆盖。删除无依据判断，补遗漏渠道或说明未覆盖；重大风险未解决就停止推荐该对象。后续技能只能引用本次证据支持的事实，新增厂商/功能/价格必须补查。

需要独立复核时按入口的[回答核验](../../references/回答核验.md)做；复核通过不能代替读来源和实际试用。

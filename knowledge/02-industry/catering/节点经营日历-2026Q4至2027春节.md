# 节点经营日历：2026 Q4 至 2027 春节

适用期：2026-10 至 2027-03。本文是经营方法和结构模板，不是客流预测、真实案例或效果承诺。2027 年放假安排以国务院办公厅的通知为准；通知发布前一律标「待核验」，本表不提供具体放假日期。节日、法定假期和门店营业安排分别核对，不能用其中一个代替另一个。农历节点、当地习惯和实际营业日期由门店确认后填写。

外卖、团购平台的节点活动规则属于实时变化的外部事实，走 `siyu-market-research` 现查；本文不写具体平台规则。节日排期是可调整的准备建议，不是全行业统一节奏。没有年夜饭供给的快餐、小吃店，可跳过预订，按真实营业与常客需求安排触达。

所有 `【填：…】` 都是未确认的事实；填完、核实后才能对客发送。缺一个关键事实就保留该占位或先问一个会改变文案的问题。没有素材时不用“客人都说”“往年爆满”等虚构见证。

## 年夜饭预订：先把供给核清，再开始发

门店先核：可订日期与时段、桌型与容量、包间余量、套餐内容及价格、是否有服务费用、订金或定金名称与规则、退改流程、预订联系人。总部无法掌握的实时余位由门店确认，不统一承诺。

统一维护门店的预订台账：意向、待确认、已确认、取消分别记录；同一桌位只有一个可售状态。总部提供台账字段和模板，门店指定接单与复核的人。询问不等于预订成功，收到款项也需按店内已确认规则给出书面确认。订金或定金、退改的表述只提醒写清能不能退、怎么退，不替用户下法律结论。

下面每个阶段各有一段朋友圈、一段群发、一段私聊。只取当前阶段所需的模板，不一次给顾客发完全部流程。

### 1. 预热：确认兴趣，不承诺未确定的供给

朋友圈：
```text
今年想在【填：门店】吃年夜饭的朋友，我们正在准备【填：真实供给方向】。你更关心人数安排，还是包间？可以私信说说需求，正式预订信息确认后再告诉你。
```

群发：
```text
年夜饭准备中。计划在【填：门店】聚餐的朋友，可以私聊告诉我们大致人数和想来的时段。现在先登记意向，套餐和预订规则确认后再发，暂不锁位。
```

私聊：
```text
收到你的年夜饭意向了。方便说一下大致人数和希望的时段吗？目前先登记需求；可订信息确认后我再回复你，登记意向还不代表已留桌。
```

承接动作：把人数、时段和联系方式按已获同意的范围记进意向栏，确认供给后联系。常见坑：把意向数当成交数、提前承诺包间、没核套餐就先收款。

### 2. 开订：让顾客看懂卖什么、如何确认

朋友圈：
```text
【填：门店】年夜饭开始预订。可订【填：日期与时段】，套餐【填：套餐内容及套餐价】，可订包间【填：包间数及适用人数】。预订按【填：订金或定金规则】办理；退改方式是【填：能否退及怎么退】。私信人数和时段，我先替你核余位。
```

群发：
```text
年夜饭开订了：【填：日期与时段】，【填：套餐内容及套餐价】。预订和退改规则：【填：订金或定金规则、能否退及怎么退】。有需要请私聊【填：接单联系人或入口】说人数、时段，我们核对余位后回复确认。
```

私聊：
```text
你问的【填：日期与时段】，目前可安排【填：已核实的桌型或包间】。套餐是【填：套餐内容及套餐价】，其他费用【填：有无及明细】。预订按【填：订金或定金规则】，退改按【填：能否退及怎么退】。你看好这些规则后，我再核位并办理确认。
```

承接动作：核位、展示完整规则、顾客确认、登记预订，再给确认凭据。常见坑：总部统一写库存、省略费用、承诺“最低价”或“保证有位”。

### 3. 催订：只说真实余位，允许顾客不回复

朋友圈：
```text
计划来【填：门店】吃年夜饭的朋友，可以开始确认人数和时段了。截至【填：余位核对时间】，可订的是【填：真实余位】。想了解套餐与预订规则，私信我查一下；是否预订由你决定。
```

群发：
```text
更新一下年夜饭预订情况：截至【填：核对时间】，【填：日期与时段】可订【填：真实余位】。还在安排聚餐的朋友，可以私聊核位，套餐与退改规则一并发给你。
```

私聊：
```text
你之前问的【填：时段】，截至【填：核对时间】还有【填：真实余位】。如果人数和时间已经定了，我可以继续帮你确认；暂时没定也没关系，有需要再联系我。
```

承接动作：每次发送前核台账，回应后转预订流程，不把沉默当作同意。常见坑：虚构“最后一桌”、每天重复催同一人、用回复次数当订位量。

### 4. 锁位：确认凭据只发给本人

朋友圈：
```text
年夜饭预订后，请留意【填：门店确认渠道】发来的确认信息。日期、时段、人数、套餐和退改方式都要核对；没收到确认的朋友可以私信【填：联系人】查询。
```

群发：
```text
已办理年夜饭预订的朋友，请私下核对门店发来的确认信息。有日期、人数或套餐变动，请联系【填：联系人】按【填：已确认的变更流程】办理；群里不用发订单或付款信息。
```

私聊：
```text
和你核对一下：预订【填：日期与时段】，【填：人数及桌型】，套餐【填：套餐内容及套餐价】，预订款【填：已核实金额与性质】，凭据【填：本人确认编号或入口】。退改方式：【填：能否退及怎么退】。请确认这些信息；最终状态以【填：门店确认方式】为准。
```

承接动作：接单与余位复核同步更新，向本人发确认信息，错误及时更正。常见坑：不同人同时卖同一包间、在群里晒付款截图、把“我帮你看看”当已锁位。

### 5. 到店前提醒：给安排，不借机追加促销

朋友圈：
```text
准备来【填：门店】吃年夜饭的朋友，位置和到店提示放这里：【填：已核实地址及到店提示】。临时有人数或时间变动，请提前联系【填：联系人】核对安排。
```

群发：
```text
年夜饭到店提示：【填：门店地址与营业安排】，预订客人请按本人确认信息到店。如需变更，请私聊【填：联系人】核对，不在群内公开订单信息。
```

私聊：
```text
提醒你，预订是【填：日期与时段】，人数【填：已确认人数】，到店位置【填：已核实地址】。如有人数、忌口或时间变动，请联系【填：联系人】确认我们能否安排；未经确认的调整先不承诺。
```

承接动作：只向对应预订客人核对信息，变动由门店确认并回写台账。常见坑：把提醒群发给所有顾客、再次索取不必要的个人信息、擅自保证特殊饮食要求都能满足。

### 6. 节后回访：听反馈，客诉先处理

朋友圈：
```text
谢谢来【填：门店】聚餐的朋友。如果用餐中有需要改进的地方，可以私信【填：反馈联系人】告诉我们。接下来的营业安排是【填：已核实营业信息】，有需要随时联系。
```

群发：
```text
感谢大家来【填：门店】聚餐。对菜品或服务有反馈，可以私聊【填：联系人】，我们逐条核对处理。后续营业安排：【填：已核实营业信息】。
```

私聊：
```text
想听听你这次在【填：门店】吃年夜饭的感受，有哪一处需要我们改进？你愿意说，我就记录并交给门店核对；如果有还没处理完的问题，我们先把它处理好。
```

承接动作：回复先归到服务反馈，有未结客诉先处理，满意反馈要征得同意才能对外引用。常见坑：回访直接推储值、把沉默写成满意、用奖励换好评。不要使用集赞、转发、拉人作为送菜或参与条件；可改为无需分享的到店礼或公开报名，权益与履约条件必须由门店确认。

## 春节营业通知：门店确认后再发

朋友圈：
```text
【填：门店】春节营业安排已确认：营业【填：日期与时段】，休店【填：日期与时段或无】，恢复【填：恢复营业时间】。预订、取餐或到店前需要核对，请联系【填：联系人或入口】。
```

群发：
```text
春节营业通知：【填：门店】营业【填：日期与时段】，休店【填：日期与时段或无】，恢复【填：恢复时间】。取餐或预订安排：【填：真实安排】。有变动我们会及时更正，请以本店确认信息为准。
```

私聊：
```text
你问的【填：日期与时段】，本店安排是【填：已核实是否营业及服务范围】。如需预订或取餐，可以【填：下一步联系或下单方式】；我会先确认本店能否安排。
```

承接动作：各店负责人签认自己的营业信息，渠道同步；总部汇总时标注更新时间和适用门店。临时变更要联系受影响的预订客人，不能只改朋友圈。

## 节后开工复苏：先提供有用信息

朋友圈：
```text
【填：门店】已按【填：真实营业时间】恢复营业。回来上班、想解决一顿饭的朋友，可以看看【填：真实可供产品与下单方式】。需要先确认取餐或用餐时间，私信我即可。
```

群发：
```text
开工用餐提醒：【填：门店】营业【填：已核实时段】，现在可供【填：真实产品与价格】。预订或取餐请走【填：入口】，有时间要求的先联系我们确认。
```

私聊：
```text
你之前问的【填：已知用餐需求】，现在本店可以安排【填：真实供给与时间】。如果最近还需要，我可以帮你核对；需求变了也没关系。
```

承接动作：只向有相关需求、允许联系的常客发送，处理回复后再谈促销。比较前后表现时记录触达人数、询问人数、确认预订与实际到店，保持观察窗一致；没有记录时不写效果结论。

## 直营 / 加盟执行边界

总部提供：阶段模板、事实字段、预订与退改口径、台账字段、纠错流程及使用说明；区域层负责通知和核对反馈。加盟店自行确认套餐、价格、供给、营业和退改规则，总部不能替门店承诺包间或折扣，也不把统一转发当作门店已执行。

门店填写：自己的日期时段、实时余位、套餐内容与价格、额外费用、预订款规则、退改方式、联系人和下单入口。直营店也要核实际供给，中央统一的事实与各店差异分开写。每条客户文案只展示对应门店的已确认事实；缺事实就保留占位并标“填完核实后可发”，不是虚构一条“可直接发”的广告。

发送前核对：事实有出处、余位有更新时间、退改写得懂、承接有人处理、没有分享换权益或绝对化价格承诺。主张无需的能力不强加；只要一段通知时，给一段通知和一个接单动作就够。

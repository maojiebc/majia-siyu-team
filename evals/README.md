# 装和不装比

这个包只有一个价值：模型读了它以后，比没读时答得好。判断好不好只看这里的盲评，不看测试通过了多少项。

## 题目

[`questions.json`](questions.json)，每题三个字段：

- `request`：用户的原话，答题方只看这个。
- `evidence`：已知限制，只给评审看，用来判断有没有超出证据下结论。
- `source`：题从哪来。目前是 10/19 的试用改写、合成场景和维护者写的题库；真实老板问的问题收到后优先加进来，并在 `source` 里写明。2026-10-22 加了第一道从真实使用反馈改写的题（`assigned_task_unconverted`）。

## 怎么跑

1. **答题**：每个版本开一个全新的对话（或子代理），按顺序答完全部题，每题当成新对话。不装技能的那组不读任何技能文件；装技能的那组只读对应版本的技能包。大家都不联网，只用题目里的信息。答案存成 `[{"id", "answer"}]`。几组同时跑时，每组的草稿和拼接脚本只放在自己的工作目录；2026-10-21 第四轮第一次跑就因为两组共用一个临时目录，前 6 题答案互相覆盖，整轮作废重跑。打乱前先确认不同组的答案没有一字不差的。
2. **打乱**：
   ```bash
   python3 tools/ab_eval.py blind --questions evals/questions.json \
     --answers bare=answers-bare.json v181=answers-v181.json v2=answers-v2.json \
     --seed 20261020 --out evals/runs/<日期>
   ```
   生成 `blind-packet.json`（给模型评审）、`blind-packet.md`（给真人评审）和 `blind-key.json`（解盲键，评完才看）。
3. **评审**：另开一个全新的对话，只给它 `blind-packet.json`，不告诉它有哪些版本、改了什么。每份回答打两项：严重错误数（编造事实、超出证据下结论、会让门店吃亏的建议），有用程度 1–5（有经验的私域负责人看了会不会照着做）；再选出最想要的一份。结果存成 `blind-review.json`。
   - 从 2026-10-21 第四轮起，按马甲本人盲评时看重的两点补进模型评审的标准：读者是没耐心的老板，结构清楚、好读算加分；朋友圈和群消息没有 emoji、读着平淡要扣分。
   - 真人评审用离线审阅页：`python3 tools/review_page/build.py --run evals/runs/<日期> --arms "分别来自：……" --out 审阅台.html`，在浏览器里打分后导出，`blind_review` 一段存成 `<run>/human/blind-review.json`。
4. **统计**：
   ```bash
   python3 tools/ab_eval.py tally --run evals/runs/<日期>
   ```
   一题里 A 胜 B：严重错误更少；一样多时，有用程度分更高。结果写进 `results.md`。

## 怎么读结果

- 模型评审和真人评审分开写，不合成一个数。两边意见冲突时以真人为准：模型评审测不出马甲的 IP 露出值多少，也会把他凭经验的判断扣成“断言”。
- 题少的时候只能说"这些题上"，不能说普遍更好。
- 某个改动让结果变差，就撤掉这个改动；不为了好看删掉对照组答得好的题。
- 回答更长、模板更多不算进步。

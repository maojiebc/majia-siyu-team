# 回答可靠性迭代：2026-10-19

本轮修复由一份“10家火锅店需要什么系统”的实际试用回答触发。它先给确定采购架构，后问直营/加盟和现有系统；用域名和核验日期支撑“已核验在营”，遗漏重要历史风险。原文及独立复核留在维护者本机，未放进公开仓库。这里仅收录合成场景和模型实验。

## 改动

入口与问诊先判需求，只补会改变建议的条件；既有资料可做注明边界的初筛，不因不能联网而拒绝所有分析。停止强制逐层问诊和凭规模默认采购。

市场调研区分主体、在售、风险和适配，增加负面事件与解决证据。候选覆盖相关公域平台、生态服务商、独立系统和沿用系统加接口；餐饮团购/外卖包含美团生态检索，微信、支付宝等按链路纳入，百度等按实际渠道决定。平台自营、投资、认证和普通接口合作分别核验，不把背景当互通能力或流量承诺。

Python Judge 先收原始要求、答案和来源，四项可靠性检查为独立阻断条件，不参与加权补分。材料变化会使旧评分失效。辅助 CLI 随单入口包分发；它检查输入与评审结果，不调用模型或自动核验网页。Prompt-only 仍依靠模型执行，不宣称程序强制拦截。

## 行为实验

[六个固定场景](../../../tests/fixtures/answer_quality/scenarios.json)分别是条件不足的火锅选型、含历史结算风险的虚构厂商初筛、平台覆盖、不换系统的小动作、安静但持续核销的群、明确条件的短通知。厂商及 example 域名为合成材料，不是市场事实。

无技能、旧版、修改版各用一个全新代理上下文作答，模型继承当前会话配置，每版本内连续处理六题。每题随机排列 A/B/C 后，由另一个新上下文只看用户要求、证据和匿名答案评审。未传版本名或改进目标。随机种子为 20261019。

| 对比 | 修改版优于对照 | 并列 | 劣于对照 |
|---|---:|---:|---:|
| 旧版技能 | 3 | 3 | 0 |
| 不加载技能 | 1 | 5 | 0 |

改善集中于条件性初判、利用现有资料初筛、明确的门店动作。平台覆盖题三版都可用，不能把新增规则本身算成实测提升。旧版在材料初筛题拒绝给对象判断；这是有用性/任务完成问题，不是凭空声称厂商状态。修改版六题未被此评审标记严重错误，但六题不能估计真实错误率。

原始实际试用回答另交独立评审，事实、适配、风险三项 fail，覆盖 unknown；新 CLI 返回 blocked、退出码1，无分数/徽章。这个结果只说明新流程在给定证据下能拒绝该回答，不证明原生成器当时读取了哪些材料，也不证明以后不会再生成错误。

## 可复核材料与限制

三个 answers.json、匿名盲评结果、解盲键和 manifest.json 保留完整输出、来源分支与哈希。旧技能基于 4ee6174，修改版测试使用当轮三技能快照；随后增加评审工具说明、压缩入口文字、调整语言要求，并统一路由、编排和老板版指南中的初筛与经营边界；这些后续文本修改未再做模型对比实验。完整快照及用户原回答复核保留在本机实验目录。

这是单次模型自测，一位模型评审；具体模型修订号与采样参数未由代理工具暴露。不属于人工盲评、线上真实选型、全宿主回归或 Pilot H1；H1/H2/H3 状态不变。结论只限于这六题，不能声称技能普遍优于通用模型。

后续新增高频失败场景时，沿用相同条件对比；不为提高胜率删掉基线更好的答案，也不把更多模板或更长回答当进步。

## 工程验证

最终源码在 Python 3.12、安装检查强制开启的条件下通过 `make check`：407 项测试，无跳过；独立 wheel 与单入口包检查包含在内。CI 同款 pytest 单元入口、Ruff 与 Mypy 也通过。独立代码复核未发现阻断问题。以上是本机结果，不等于线上宿主更新或经营效果验收。

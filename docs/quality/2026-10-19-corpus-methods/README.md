# 跨行业文案与配图方法接入

维护者要求从已有私域营销存档中提炼文案、图片、渠道、欢迎、评论与时间安排。本次采用目的抽样，细读36条分渠道记录（各渠道12条，部分为卡片标题与描述），7组朋友圈正文及其首张已配对原图，6条原生作者评论及其5条父动态，另看欢迎与评论截图各1张。样本涉及餐饮饮品、服饰、美妆、生鲜、日用、旅游和平台权益；品牌归属不作为本次方法的成立依据。

目的抽样不是代表性抽样。原生确认欢迎记录为空，欢迎分析依赖既有人工确认截图；7张配图来自朋友圈，未验证私聊或门店群卡片封面；只看首图不评价整组完备性。没有点击、完整送达、核销或订单证据，不判断经营效果。原文、图片、账号、品牌活动参数、路径和映射仅保留在维护者本地，未上传或改动原件。

## 本次采用的内容

[分渠道文案与触达节奏](../../../knowledge/00-methodology/分渠道文案与触达节奏.md) 按场景、比较、组合、资格、服务和品牌任务选写法；分清朋友圈、日常1V1、门店群与欢迎阶段；安排正文、图、卡片和作者评论的职责，分开发帖、评论、有效期与归档更新时间。

[文图协作与生图简报](../../../knowledge/00-methodology/文图协作与生图简报.md) 把信息关系落实到场景展示、并列比较、整体加部件、资格分组和步骤组织，提供设计简报与验收流程。没有实际生成新图或做设备预览，不宣称生图能力验收。

这些内容选取并重新审读了 `docs/operating-judgments/` 中的有关机制，没有整体批准所有研究候选。采纳的是条件性生成规则，非经转化数据验证的成功规律。

## 实际可达范围

朋友圈、群发、欢迎话术和内容策划四个技能直接链接新参考；源码、Python包内知识文件、SkillHub与WorkBuddy生成包同步。未增加新的路由任务类型，也未把两份参考变成知识原子，严格原子集仍为49条。Python计划中的原子选择不等于已自动读取新参考；宿主应按执行技能链接读取有关段落。

同步删除固定爆款结构、符号配额、群发黄金时段、新人触达次数和无条件购买动作等旧冲突。审查另修正群发强制动作/排期，以及“修违规措辞顺手增加赠品或专属价”的示例和不实扫描状态要求。

## 行为验证与限制

独立上下文先按旧技能回答三个合成任务，再由另一上下文按新版包回答同三题，附加时间字段与缺封面的任务。两边都避开了主要目标风险，不能声称已复现旧版失败或证明新版优于旧版。新版实际读取了四个技能及两份方法；完整回答见 [行为记录](behavior-answers.md)。这不是盲评，不计算胜率，也不更改H1/H2/H3状态。

参考残留修正后，追加一条纯营业通知，检查不凭空添加活动动作。模型回答只证明这几次遵循情况，不是WorkBuddy真实新会话或经营验收。检查脚本未在模型试用中运行，回答如实保留未运行状态。

# 飞书同行知识共建 Base 结构

目标 Base：`连锁餐饮私域同行共建知识库`

- 飞书知识库节点：<https://supermjbc.feishu.cn/wiki/XdrvwbtIyif61Pku8yQcSCj6nWf>
- 对外案例采集表单：<https://supermjbc.feishu.cn/share/base/form/shrcnLsRQgaQJilUGNg6BjBXflg>

实际部署包含六张核心治理表和一张表单接收表。接收表只承载对外问卷，避免飞书表单自动把审核状态、安全扫描、质量分等内部字段暴露给填写人。

飞书用于协作采集和人工审核，不是 Runtime 的实时知识真源。只有人工审核通过、进入发布批次并导出到版本化 JSONL 的原子，才允许进入正式检索。

## 1. 主题征集

| 字段 | 飞书类型 | 说明 |
|---|---|---|
| Topic ID | 自动编号 | `TOPIC-001` |
| 主题名称 | 文本 | 当前只开放 1—2 个窄主题 |
| 核心问题 | 文本 | 需要验证的具体矛盾 |
| 所属知识包 | 单选 | 首期为“加微入口与门店承接” |
| 开始日期 / 截止日期 | 日期 | 两周一期 |
| 目标案例数 / 目标原子数 | 数字 | 首期 15 / 15 |
| 当前案例数 / 审核通过原子数 | 数字 | Phase 0 先人工维护，后续再做汇总字段 |
| 状态 | 单选 | 筹备中 / 征集中 / 整理中 / 已发布 |
| 表单链接 / 结果报告 | URL 文本 | 外部入口与复盘 |
| 对外征集文案 | 文本 | 可复制邀请文案 |
| 主题召集人 | 文本 | Phase 0 先用文本，后续关联贡献者 |
| 进入版本 | 文本 | 知识版本，不等于代码版本 |

## 3. 知识原子

保存 AI 初步提炼后、等待人工审核的 KnowledgeAtomV2。贡献者不直接填写。

核心字段：`Atom ID`、`核心判断`、`类型`、`主题`、`对应 Skill`、`行业`、`子行业`、`业务模式`、`生命周期`、`渠道`、`组织角色`、`成立条件`、`建议动作`、`验证指标`、`失败模式`、`失效边界`、`证据等级`、`置信度`、`来源案例`、`来源定位`、`贡献者确认`、`Review Status`、`审阅者`、`审阅日期`、`公开范围`、`Client ID`、`Exportable`、`Valid From`、`Valid Until`、`Supersedes`、`Contradicts`、`进入版本`、`被调用次数`、`有效反馈数`、`无效反馈数`、`最近复核日期`、`修订建议`。

硬门：只有 `Approved` 且进入正式发布批次的原子可以导出；`client_private` 和 `Exportable=false` 永不进入公共 JSONL。

## 4. 贡献者

字段：`Contributor ID`、`对外名称`、`内部联系方式`、`当前角色`、`擅长主题`、`允许署名`、`默认授权范围`、`提交案例数`、`Qualified 案例数`、`Approved 原子数`、`被调用次数`、`有效验证次数`、`共创身份`、`最近参与日期`、`备注`。

不按提交量排名；重点看审核通过、真实调用、使用验证和独特性。

## 5. 使用反馈

字段：`Feedback ID`、`Atom ID`、`Bundle ID`、`Trace ID`、`使用场景`、`用户角色`、`业务背景`、`是否采纳`、`实际动作`、`结果类型`、`实际结果`、`新增成立条件`、`新增失效边界`、`是否建议修订`、`授权范围`、`安全扫描`、`审核状态`、`创建时间`。

明确反例、明显副作用或两个以上结构相似的无效反馈，应把原子重新送入 `In Review`，不能直接自动废弃。

## 6. 发布批次

字段：`Release Batch ID`、`目标版本`、`包含原子`、`新增数量`、`修订数量`、`废弃数量`、`公共原子数`、`私有原子数`、`导出状态`、`PR URL`、`CI 状态`、`合并状态`、`发布说明`、`发布日期`、`Corpus Version`、`Corpus Checksum`。

飞书修改不会实时影响线上。只有选入明确批次、通过 Schema/隐私/重复/冲突检查并合并 PR 后才生效。

## 7. 问卷提交（自动同步）

这是飞书原生表单的直接同步表，不属于六张核心治理表。包含 21 个对外问题字段，以及系统生成的 `Submission ID` 和 `提交时间`。

- 15 个必填问题覆盖角色、业务模式、门店规模、渠道、案例类型、事件、原判断、真正原因、改后动作、结果证据、成立条件、是否亲历、授权和保密确认。
- 选填项包括改前动作、失效边界、补充访谈、附件、对外名称和联系方式。
- Phase 0 由人工做安全扫描和案例质量判断，再将合格内容转入“原始案例”。
- 后续若实现同步器，也只能创建 `Submitted` 原始案例，不得自动生成或批准知识原子。

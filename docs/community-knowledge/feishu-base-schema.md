# 飞书同行知识共建 Base 结构（v1.2.1 Pilot）

目标 Base：`连锁餐饮私域同行共建知识库`

- 现有飞书知识库节点：<https://supermjbc.feishu.cn/wiki/XdrvwbtIyif61Pku8yQcSCj6nWf>
- v1.2.1 公开采集表单：<https://supermjbc.feishu.cn/share/base/form/shrcnLsRQgaQJilUGNg6BjBXflg>

六表仍保留为治理蓝图，v1.2.1 Phase 0 日常只激活两类工作面：

1. `案例提交与审核（v1.2.1）`：原生表单同步、安全检查、质量判定、补问与人工分钟。
2. `知识原子与确认`：Draft 提炼、脱敏、回传确认与人工审批。

`主题征集`、`贡献者`、`使用反馈`、`发布批次` 先用字段、视图或人工文档维护，不要求日常重复填写。六张治理表仍保留；公开表单已在原分享链接上切换为 v1.2.1。切换前确认同步表无真实投稿，因而移除了 v1.2.0 的 21 题旧字段，没有删除真实案例。

飞书用于协作采集和人工审核，不是 Runtime 的实时知识真源。v1.2.1 不开发飞书 API 和 Runtime 注入。

## 1. 主题征集

| 字段 | 飞书类型 | 说明 |
|---|---|---|
| Topic ID | 自动编号 | `TOPIC-001` |
| 主题名称 | 文本 | 当前只开放 1—2 个窄主题 |
| 核心问题 | 文本 | 需要验证的具体矛盾 |
| 所属知识包 | 单选 | 首期为“加微入口与门店承接” |
| 开始日期 / 截止日期 | 日期 | 两周一期 |
| 目标案例数 / 目标原子数 | 数字 | 首期 15 / 15 |
| 当前案例数 / 审核通过原子数 | 数字 | Phase 0 先人工维护，后续再做汇总字段 |
| 状态 | 单选 | 筹备中 / 征集中 / 整理中 / 已发布 |
| 表单链接 / 结果报告 | URL 文本 | 外部入口与复盘 |
| 对外征集文案 | 文本 | 可复制邀请文案 |
| 主题召集人 | 文本 | Phase 0 先用文本，后续关联贡献者 |
| 进入版本 | 文本 | 知识版本，不等于代码版本 |

## 2. 案例提交与审核（v1.2.1 Phase 0 活跃表）

公开表单直接同步到该表，当前线上名称为 `案例提交与审核（v1.2.1）`。通过人工初审的内容才是后续提炼的证据来源；表单提交永远不等于正式知识。

| 字段 | 飞书类型 | 必填 |
|---|---|---:|
| Submission ID | 自动编号 | 系统 |
| 所属主题 | 关联“主题征集” | 是 |
| 对外名称 / 联系方式 | 文本 | 否 |
| 贡献者角色 | 多选 | 是 |
| 业务模式 | 多选 | 是 |
| 门店规模 | 单选 | 是 |
| 主要渠道 | 多选 | 是 |
| 案例类型 | 单选 | 是 |
| 发生了什么 | 多行文本 | 是 |
| 最初判断 / 真正原因 | 多行文本 | 是 |
| 改前动作 | 多行文本 | 否 |
| 改后动作 / 结果证据 / 成立条件 | 多行文本 | 是 |
| 失效边界 | 多行文本 | 否 |
| 是否亲历 / 保密确认 | 勾选 | 是 |
| 授权范围 | 单选 | 是 |
| 是否接受补充访谈 | 单选 | 否 |
| 附件 | 附件 | 否 |
| 安全扫描 | 单选 | 自动/人工 |
| 案例质量分 | 数字 | 人工 0—10 |
| 审核状态 | 单选 | Submitted / Need Info / Qualified / Rejected |
| 审核备注 | 文本 | 否 |
| 首次阅读 / 补问 / 提炼 / 脱敏 / 确认 / 入库分钟 | 数字 | 人工，缺失留空 |
| 补问次数 / Draft 原子数 / 确认原子数 | 数字 | 人工 |
| 案例卡交付 / 5 个工作日内 | 勾选 | 人工 |
| 愿意再次参与 / 交换价值评分 | 单选 / 数字 | 人工，1—5 分 |
| 创建时间 / 更新时间 | 系统时间 | 系统 |

## 3. 知识原子与确认（Phase 0 活跃表）

保存 AI 协助草拟后、等待人工审核的 KnowledgeAtomV2。贡献者不直接填写，确认也不会自动提高证据等级。

核心字段：`Atom ID`、`核心判断`、`类型`、`主题`、`对应 Skill`、`行业`、`子行业`、`业务模式`、`生命周期`、`渠道`、`组织角色`、`成立条件`、`建议动作`、`验证指标`、`失败模式`、`失效边界`、`证据等级`、`置信度`、`来源案例`、`来源定位`、`贡献者确认`、`Review Status`、`审阅者`、`审阅日期`、`公开范围`、`Client ID`、`Exportable`、`Valid From`、`Valid Until`、`Supersedes`、`Contradicts`、`进入版本`、`被调用次数`、`有效反馈数`、`无效反馈数`、`最近复核日期`、`修订建议`。

硬门：只有 `Approved` 且进入正式发布批次的原子可以导出；`client_private` 和 `Exportable=false` 永不进入公共 JSONL。

## 4. 贡献者

字段：`Contributor ID`、`对外名称`、`内部联系方式`、`当前角色`、`擅长主题`、`允许署名`、`默认授权范围`、`提交案例数`、`Qualified 案例数`、`Approved 原子数`、`被调用次数`、`有效验证次数`、`共创身份`、`最近参与日期`、`备注`。

不按提交量排名；重点看审核通过、真实调用、使用验证和独特性。

## 5. 使用反馈

字段：`Feedback ID`、`Atom ID`、`Bundle ID`、`Trace ID`、`使用场景`、`用户角色`、`业务背景`、`是否采纳`、`实际动作`、`结果类型`、`实际结果`、`新增成立条件`、`新增失效边界`、`是否建议修订`、`授权范围`、`安全扫描`、`审核状态`、`创建时间`。

明确反例、明显副作用或两个以上结构相似的无效反馈，应把原子重新送入 `In Review`，不能直接自动废弃。

## 6. 发布批次

字段：`Release Batch ID`、`目标版本`、`包含原子`、`新增数量`、`修订数量`、`废弃数量`、`公共原子数`、`私有原子数`、`导出状态`、`PR URL`、`CI 状态`、`合并状态`、`发布说明`、`发布日期`、`Corpus Version`、`Corpus Checksum`。

飞书修改不会实时影响线上。只有选入明确批次、通过 Schema/隐私/重复/冲突检查并合并 PR 后才生效。

## 7. 公开表单与迁移记录

公开表单与 `案例提交与审核（v1.2.1）` 原生同步，不属于六张治理蓝图表。当前表单共 13 题：7 个核心问题、5 项轻量元数据和 1 个可选语音/附件入口。

- 原 v1.2.0 表单共有 21 个对外问题字段；切换前同步表记录数为 0，因此旧问题字段已清除，不存在历史投稿丢失。
- 分享链接保持不变，原有访问入口无需迁移。
- 系统字段 `Submission ID` 和提交时间继续保留。
- Phase 0 由人工做安全扫描、质量判断、脱敏、确认和审批；表单不得自动生成或批准知识原子。

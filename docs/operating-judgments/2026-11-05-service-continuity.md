# 服务承接也要说明暂不可用时怎么办

日期：2026-11-05。J27为研究候选，对[J02：信任来自可以兑现的细节](2026-10-14-private-domain-judgments.md#j02--信任来自可以兑现的细节)补充适用情境；未验证入口可用、实际响应、关系迁移或经营效果。

## J27 · 按顾客状态安排服务的下一步

判断：给出服务入口后，还需要说明它当前能处理什么。旧触点不能回应、受理延迟或关系需要迁移时，可以区分顾客已经完成的动作、可自助确认的事项，以及确实需要人工处理的事项。不能只把所有人再次导向同一个入口。

观察依据：已读材料中，一类沟通把订单确认与需要人工处理的修改分开，并说明受理限制；另一类说明旧触点的回应限制、后续接续方式，以及已经完成接续的人无需重复操作。这些都是发送方的表述，没有证明实际服务能力。

机制假设：状态和责任说明可能减少等待中的不确定、重复询问和重复操作。该假设仍需验证，不能直接宣称提升信任、留存或转化。

成立条件：新旧身份、处理权限、当前目标及业务规则已经核实；所写的自助路径和人工安排真实存在。服务发生变化的原因不必由文案猜测，响应时间也只能承诺本方确实能够保证的部分。

反例：已能自助完成的事项，不必为了维持对话而转人工；已经完成接续的人，不应再被要求重复操作。临时受理缓慢不等于完全没有服务；发送方说触点停用，也不能据此认定平台处罚、人员变化或关系已经迁移成功。

生成规则：先识别顾客当前状态和下一项必要动作，再安排可用入口、能力边界、可保证的时间信息及必要回查方式。区分已经完成者与尚未完成者，区分申请与保证兑现，不用亲切语气替代实际安排。没有可核验目标时留待业务确认，不自行补造账号、地址或处理时限。

证据限制：当前只有沟通内容，没有入口打开、目标身份复核、排队、实际处理与后续留存记录。资料页、欢迎语、私聊和群公告可以共同承接，但是否减少寻找与重复操作，需要独立验证。

待验证问题：顾客能否判断自己下一步该做什么？重复咨询或重复操作是否减少？自助确认与人工处理是否各自完成？无法立即处理时，预期是否与实际兑现相符？

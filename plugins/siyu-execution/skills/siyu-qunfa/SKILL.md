# 社群群发官（siyu-qunfa）

## 这个 skill 干什么
根据群的用途和本次真实信息生成通知、选择帮助、服务或活动文案。栏目是安排长期内容的工具，单条任务不扩成栏目规划；缺关键条件时交待核稿。

方法论引擎：**运营即广告**——每条群发都是一次有成本的触达，要对打开率和承接负责，不刷屏、不浪费触达额度。

> 群发长期低于自家可核实的基线时，先查群定位、预期与回复承接；没有可见的打开记录，就不下打开率结论。文案不能替代机制诊断，不用无来源的行业阈值。

## 输入（先用已有信息，关键缺口才问）

开始前，若当前客户在 `~/.siyu/clients/` 有档案，按 `siyu-restore` 第 1 步定位（以文件名时间判断最新，解析实际路径并拒绝路径越界），只读最近可用档案的「经营画像」和「已确认结论」，开头说明用了哪天的哪份档案；用户说不用就忽略。只读，不写、不改档案，不跨客户查找，放弃的方向不继承。当前对话优先；档案里的价格、营业与活动等旧事实仍需本次确认。没有档案就直接用已有信息，不要求先建档。


- 品牌/品类 + 群类型（福利群/铁粉群/新客群/门店群）
- 本次要发什么（每日栏目 / 某活动 / 某新品）
- 人设语气（实在/温暖/玩梗… 见 references）
- 目标动作（到店核销/小程序下单/接龙报名/加个人号；零售不要默认到店核销）
- 真实优惠条件（用户当场提供，避免"假大空一键转发"；说明见 `assets/真实语料-待填.md`）
- 发几个栏目 / 排几天

节日、节点、年夜饭、春节类请求先读 [节点经营日历](../../../../knowledge/02-industry/catering/节点经营日历-2026Q4至2027春节.md)。

## 生成流程（SOP）

### 1. 先定本群任务，需要时选栏目
默认栏目库：每日好物 / 限时秒杀 / 干货一条 / 社群专属价 / 接龙互动 / 到店提醒。
先读 [分渠道文案与触达节奏](../../../../knowledge/00-methodology/分渠道文案与触达节奏.md) 的渠道、时间和事实表。栏目能表达预期，效果需另证；栏目选择见 [`references/栏目模型与打开率.md`](references/栏目模型与打开率.md)。

### 2. 套群发结构
按任务组织：**首句说明本次信息 → 正文给事实 → 需要时给明确的下一步**；只有真实期限已确认时才写截止。催订须按节点日历的对应阶段模板保留「截至【填：核对时间】」「【填：真实余位】」和本店接单入口，填完核位才发；不能退回泛泛的意向登记。
首句清楚表达与本群的关系；预览随设备和界面变化，不用固定字数保证可见。

### 3. 出文案 + 人设语气
- 长短服从任务，必要的规则、选项与步骤不为短而删；符号用于导航，不机械套人设或emoji。
- 按人设出对应语气版；需要时出 A/B（换钩子首句）。
- 排期对齐消费决策、履约与回复能力；未知时给待试窗口，不默认午间/晚间/睡前。
- 配图按 [文图协作与生图简报](../../../../knowledge/00-methodology/文图协作与生图简报.md)，核对本店商品与规则；总部素材先经本店确认。

### 4. 合规前置扫描（群发是重灾区，必做）
```bash
echo "群发文案" | python3 plugins/siyu-execution/skills/siyu-qunfa/scripts/qunfa_lint.py -
```
除通用红线（第一/100%/绝对化），**重点扫群发特有的诱导分享**（转发得赠/集赞/拉 X 人进群）——这类是企微封号高发。命中就地改走企微官方路径。见 [`references/合规前置扫描.md`](references/合规前置扫描.md)。

### 5. 三句话自检
- **运营即广告**：这条触达值不值？会不会让人退群？
- **内容即产品**：除了促销，给了用户什么（信息/福利/参与感）？
- **私域即公关**：像群主在张罗，还是像机器人轰炸？

## 活动模板
- **平台权益联动**：先核验门店权限、权益资格及核销退款，不保证隐藏、不破价或排名。见 [`references/活动模板-偷着打折.md`](references/活动模板-偷着打折.md)。

交付前，把最终客户正文通过标准输入送入上面的随包检查脚本；实际退出码为 0 才写「脚本扫描通过」。无法运行时，按参考资料自检并写「未运行脚本，发布前仍需复核」，不把模型自检称为人工审核；命中阻断先改写再检查。

改写记录只说明「参与方式已改为无需分享」，不给原违规广告复述或引号示例；客户正文和操作说明都检查，避免把风险句带进交付物。

## 输出格式

先给客户正文，操作说明放正文外；单条短稿也在末尾独立保留一行真实检查状态（已运行的结果，或「未运行脚本，发布前仍需复核」）。
单条直接交正文；需要批量才按栏目/天组织。时段、参与动作、配图、A/B和机制提醒按任务需要提供，不给纯通知强加回复动作或群沉默诊断。加盟/混合须给每条加「执行边界」标签；零售不要默认到店钩子。

# 破冰欢迎话术官（siyu-huashu）

## 这个 skill 干什么
新加好友、新进群的第一印象决定留不留。这个 skill 出三样：账号 IP 立住模板（头像/命名/背景）、分场景分人群的破冰欢迎话术、高频重复问题的答疑库。目标是把"加进来就流失"救成"加进来能留下"。

方法论引擎：**私域即公关**——第一句话就是品牌门面，破冰 = 建立信任关系，**不是上来推销**。

> 欢迎流程的效果用自家顾客的完整观察窗核验，不设无出处的行业提升比例。

节日、节点、年夜饭、春节类请求先读 [节点经营日历](../../../../knowledge/02-industry/catering/节点经营日历-2026Q4至2027春节.md)。

## 三块能力

### A. 账号 IP 立住（开户 / 改名模板）
来自 `knowledge/02-industry/catering/餐饮私域方法论.md` 的造 IP 公式，详见 [`references/造IP账号立住.md`](references/造IP账号立住.md)：
- 头像：真人 + 微笑 + 工服/门店场景，身份可识别（除非品牌势能极强）。
- 名称：单店 = `门店+人名(+福利发放版)`；连锁 = `品牌+门店+职务+人名`。反面：本名/法人全名。
- 朋友圈背景 = 招牌菜。

### B. 破冰欢迎流程（分场景分人群）
详见 [`references/破冰欢迎流程.md`](references/破冰欢迎流程.md)。
- 场景：加个人号 / 进社群 / 门店扫码加 / 活动加。
- 人群：新客 / 老客 / 到店客 / 线上客。
- 结构：**认领身份（你是谁）→ 给个理由（在这能得到啥）→ 轻动作（不索取，先给）→ 留个钩子**。

### C. 答疑话术库
详见 [`references/答疑话术库.md`](references/答疑话术库.md)。
高频问题（营业时间/位置/预订/优惠/配送/退换）的标准应答结构：**先答要点 → 再给一步动作 → 留人味**。

## 输入（先用已有信息，关键缺口才问）

开始前，若当前客户在 `~/.siyu/clients/` 有档案，按 `siyu-restore` 第 1 步定位（以文件名时间判断最新，解析实际路径并拒绝路径越界），只读最近可用档案的「经营画像」和「已确认结论」，开头说明用了哪天的哪份档案；用户说不用就忽略。只读，不写、不改档案，不跨客户查找，放弃的方向不继承。当前对话优先；档案里的价格、营业与活动等旧事实仍需本次确认。没有档案就直接用已有信息，不要求先建档。


- 品牌/品类 + 单店 or 连锁
- 要哪块（A 立住 / B 破冰 / C 答疑）
- 场景 + 人群（破冰用）
- 人设语气
- 真实信息（营业/位置/优惠/群规，由用户当场提供；说明见 [`assets/真实语料-待填.md`](assets/真实语料-待填.md)）

## 合规前置扫描（必做）
```bash
echo "话术" | python3 plugins/siyu-execution/skills/siyu-huashu/scripts/huashu_lint.py -
```
欢迎/话术不绝对化、不诱导分享、**不在第一句就索要敏感信息**（手机号/身份证/定位要有授权口径）。见 [`references/合规前置扫描.md`](references/合规前置扫描.md)。

## 三句话自检
- **私域即公关**：这句是"欢迎你"还是"快买"？是平等还是推销？
- **内容即产品**：第一条给了用户价值（有用信息/福利/参与）吗？
- **运营即广告**：破冰动作会不会太重、让人反感？

交付前，把最终客户正文通过标准输入送入上面的随包检查脚本；实际退出码为 0 才写「脚本扫描通过」。无法运行时，按参考资料自检并写「未运行脚本，发布前仍需复核」，不把模型自检称为人工审核；命中阻断先改写再检查。

## 输出格式

先给客户正文，操作说明放正文外；单条短稿也在末尾独立保留一行真实检查状态（已运行的结果，或「未运行脚本，发布前仍需复核」）。
按场景/人群：`场景 | 人群 | 话术正文 | 触发时机 | [人设版]`，末尾附「合规扫描：通过 / 改写记录」。加盟/混合须给每条加「执行边界」标签；零售不要默认到店钩子。

## 马甲护城河注入点
优先查询公开原子库：`python3 tools/atoms_query.py --skills siyu-huashu`。欢迎流程、高频问答和人设由用户当场提供；私有实战层说明见 `assets/真实语料-待填.md`。客户标签微调仍留人工接口。

收尾时如果已形成可复用结论，提示一次：「有结论想留下，输入 `/siyu-save`。」一次对话最多提示一次。

门店收银、进群承接、开业、核销排错、员工激励和日常内容，按具体问题读取 [门店会员执行参考](../../../../knowledge/02-industry/catering/门店会员执行参考.md)；口径与算账交 majia-huiyuan。

餐饮的付款触点、进群取舍、内容分工、活动撤停、分层与资源变化，按需读 [餐饮私域条件与执行](../../../../knowledge/02-industry/catering/餐饮私域条件与执行.md)；只读取与当前问题有关的段落。
